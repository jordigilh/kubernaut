### P1-1 — Registration incarnation is not safely propagated

**Evidence**

- `pkg/fleet/registry/types.go:25-44` has no registration UID.
- EAIGW and Kuadrant registries key updates/deletes by name:
  `pkg/fleet/registry/eaigw_registry.go:308-351` and
  `pkg/fleet/registry/kuadrant_registry.go:212-270`.
- Reader creation remains cluster-ID-only:
  `pkg/fleet/fmc/syncer.go:53-58,191-193` and
  `cmd/fleetmetadatacache/main.go:222-234`.

**Impact**

A delayed delete/update from an old registration can clear or overwrite a recreated
registration using the same name. A reader can also bind to the wrong incarnation.

**Correction**

Define `RegistrationUID` in registry events and reader-factory inputs. Ignore stale
events whose UID does not match the current entry. Include the UID in partition keys,
status predicates, and all reader creation. Add an explicit old-delete-after-recreate
integration case.

### P1-2 — Lease, status, and readiness lifecycle is underspecified and unwired

**Evidence**

- Current `fmcDeps` has no Lease or status-store dependency:
  `cmd/fleetmetadatacache/main.go:63-82`.
- `/readyz` currently reflects MCP readiness and Valkey ping, not registry sync, Lease
  heartbeat, migration state, or partition cleanliness:
  `cmd/fleetmetadatacache/main.go:280-312,439-478`.
- The proposed status-store API only defines cycle operations: plan `:207-219`; it has
  no lease acquire/renew/loss, readiness snapshot, or migration-barrier read.

**Impact**

A persisted `clean` state could remain trusted after Lease loss, registry loss, or stale
status. An empty registry may make the service ready while target decisions incorrectly
become unmanaged.

**Correction**

Define and wire explicit `LeaseCoordinator`, status snapshots, heartbeat expiry,
migration-barrier reads, and `FMCReadinessSnapshot`. Prove:

- empty registry after successful initial sync = service-ready, target-unavailable;
- registry loss, Lease loss, status-store failure, and stale heartbeat = unavailable;
- unknown cluster is typed unavailable, not `200 {"managed":false}`
  (`pkg/fleet/fmc/handler.go:108-112`).

### P1-3 — Server-time expiry is described but not enforced by the proposed API

**Evidence**

- Current writer uses client-side `SET` TTL: `pkg/fleet/fmc/valkey_writer.go:57-60`.
- Proposed `PutObserved` accepts a `ResourceRecord` containing `expires_at_ms`: plan
  `:192-199`.
- Server-time authority is only described narratively at plan `:233`.

**Impact**

Callers could supply application-clock expiry values or create disagreement between TTL,
stored expiry, and index score. Clock skew could extend stale authorization.

**Correction**

Make `PutObserved` accept observation data plus TTL, not caller-owned expiry. The Valkey
script must call `TIME`, calculate expiry, set `PEXPIREAT`, and return the server-derived
timestamp. Add clock-skew, `TIME` failure, PTTL disagreement, and expiry-boundary tests.

### P1-4 — GVK and supported-kind handling is not complete end-to-end

**Evidence**

- Gateway drops group/version: `pkg/gateway/signal_ingestion.go:482-487`.
- SignalProcessing history reconstruction calls `InferGVK`:
  `pkg/apifrontend/policyread/service.go:553-560`.
- Remote enrichment derives GVK from Kind and defaults unknown kinds to core `v1`:
  `pkg/signalprocessing/enricher/k8s_enricher.go:565-567,608-626`.
- FMC, shared scope, and enrichment maintain different kind catalogs:
  `pkg/fleet/fmc/syncer.go:40-51,92` and `pkg/shared/scope/manager.go:82-128`.

**Impact**

Same-kind resources in different groups can collide or be read as the wrong object.
Unsupported or uncollected kinds may incorrectly receive namespace-based authorization.

**Correction**

Create one versioned supported-GVK catalog covering collection status, scope, RBAC, and
dynamic-kind policy. Propagate explicit group/version through SignalProcessing,
enrichment, Gateway, RO, AF, history, and FMC. Remote paths must reject missing/ambiguous
GVK and never call `InferGVK`.

### P1-5 — Typed scope behavior lacks a concrete Go/API contract

**Evidence**

- Current interface remains `(bool, error)`: `pkg/shared/scope/checker.go:59-64`.
- Current handler returns boolean state and maps unknown clusters to `200 false`:
  `pkg/fleet/fmc/handler.go:77-131`.
- Current client decodes every `200` as a definitive boolean:
  `pkg/fleet/fmc/http_client.go:96-172`.
- The plan defines states conceptually but not exact interfaces, typed errors, or retry
  mappings: plan `:119-145`.

**Impact**

Unavailable, unsupported, invalid, unauthorized, and verified-unmanaged outcomes can be
collapsed differently by Gateway, RO, or AF.

**Correction**

Specify the concrete `ScopeResult`, nullable `Managed`, stable reason codes,
`ScopeChecker` signature, HTTP status mapping, retryable status mapping,
malformed-response behavior, and caller behavior. Add production-path tests for
400/401/403/404/422/503, legacy media, and malformed `200` responses.
